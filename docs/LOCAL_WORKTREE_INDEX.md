# Fast Local Worktree Index

Use the fast local worktree index as a cheap registration pass before any deep
multi-repository census. It answers which repositories and Git worktrees are
registered, which commits and branches they name, and whether Git marks a
registration detached, bare, prunable, or locked.

It deliberately does not answer whether a worktree is clean, whether ignored
or generated bytes exist, whether a commit is published, or whether a branch,
release, deployment, Pages site, device, or active owner still consumes it.
The index performs no status or ignored-path scans and makes no network call.
Its output is shortlist evidence, never deletion or publication authority.

## Three-tier use

1. **Tier 0: registration index.** Run the fast index across the complete local
   repository registry. Filter its result to a small set of exact paths.
2. **Tier 1: exact-path adjudication.** For each shortlisted path, inspect
   source and ignored bytes, head/tree identity, ancestry, canonical state,
   locks, processes, owner evidence, and reconstruction options.
3. **Tier 2: operational authority.** Add live pull-request, workflow, release,
   deployment, catalog, device, or publication gates only when that particular
   package intersects those surfaces.

Do not turn Tier 0 into a deep scan for convenience. A local proof over 30
repositories and 702 worktrees completed in about 10 seconds; the preceding
serial deep census had no terminal output after more than 16 minutes. That is
a measured lower-bound speedup above 100x, not a universal benchmark.

## Registry and command

The registry is a local JSON document with a `repositories` array, or a
top-level array of the same rows. By default, each row uses `repo_id` and
`repository_root`:

```json
{
  "repositories": [
    {
      "repo_id": "example-owner",
      "repository_root": "<absolute-or-registry-relative-checkout>"
    }
  ]
}
```

Keep machine paths and generated index reports in ignored local storage. Run:

```powershell
pwsh -NoProfile -NonInteractive -ExecutionPolicy Bypass `
  -File .\tools\Inspect-LocalWorktreeIndex.ps1 `
  -RegistryPath <local-repository-registry.json> `
  -OutPath <new-local-worktree-index.json>
```

Use `-RepositoryIdProperty` and `-RepositoryPathProperty` when an existing local
registry uses different field names. The tool refuses to overwrite an existing
report. Omitting `-OutPath` returns the same JSON on standard output.

The result uses
`rusty.morphospace.workflow.fast_local_worktree_index.v1`. It records the
registry hash, elapsed time, repository and worktree identities, accessibility,
and aggregate counts. It also records zero network, status, ignored-path, Git,
remote, and source/worktree mutations so later stages cannot mistake this pass
for deep validation.

Run the portable fixture with:

```powershell
pwsh -NoProfile -NonInteractive -ExecutionPolicy Bypass `
  -File .\tools\Test-LocalWorktreeIndex.ps1 -SelfTest
```

The fixture covers canonical and detached registrations, a locked worktree, an
inaccessible repository, object and top-level-array registry forms, custom
field names, output overwrite rejection, zero deep checks, and unchanged refs,
registrations, and source status.
