# Onboarding And Local-Skill Implementation Plan

Target release: `0.3.0`
Status: released on 2026-07-15 through a reviewed commit, tag, and GitHub
release.

## Decision

Make this repository the complete public first-run surface for a contributor:
strict environment verification, a current protocol-v2 example, and managed
local installation of the five portable skill routers. Keep live project state,
machine paths, and device evidence outside the repository.

The `0.3.0` version belongs to this work-environment protocol and tooling
surface. It does not supersede or change the separately governed Rusty
Morphospace platform/runtime baseline.

## Workstreams

1. Correctness: resolvable scaffold schema URLs, strict placeholder/repo/tool
   checks, scalar-safe aggregate failures, and deterministic Git selection.
2. Local skills: explicit Plan/Install/Verify/Update actions, dirty-source
   policy, managed hashes, generated locator, timestamped backup, and drift
   regression tests.
3. First-run workflow: v2 templates, a semantic hello workspace, next-step
   scaffold README, and concise Quick/Standard/Deep validation guidance.
4. Maintainability: docs-link and skill-template gates, public CI, contributor,
   security, changelog, release manifest, and advanced-authority doc split.
5. Instruction sync: concise state-first context router plus local-locator
   routing in all five portable skills.

## Acceptance

- A fresh temporary skill root completes plan, install, verify, drift detection,
  backup, update, unmanaged-file preservation, and final verify.
- A new scaffold and the checked-in hello workspace pass semantic protocol-v2
  validation with an inert feature lock.
- Strict Core/Quest profiles fail on required placeholders, missing repo paths,
  or insufficient Python/JDK versions.
- Quick, Standard, and Deep suites report any single failed child as failure.
- Public-boundary, documentation-link, JSON/JSONL, PowerShell, workflow, and
  Git whitespace checks pass without device work.

## Publication Boundary

Publication was separately authorized and completed through a reviewed commit,
tag, and GitHub release. The implementation does not authorize device actions
or updates to a contributor's existing unmanaged skills. CI runs both supported
PowerShell hosts against the published source.
