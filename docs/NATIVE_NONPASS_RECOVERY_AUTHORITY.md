# Independent native NONPASS custody recovery authority

This is a prospective source-policy evolution and a separate execution
authorization protocol. Its presence in a candidate is not adoption. The
original project remains the sole native planning owner. No new project,
FAST package, path admission, accepted result or runtime authority follows.

The current v4 recovery route supports units with no `tooling_context` property.
A sealed context selecting another executor and a tooling upgrade are unsupported
by this route. The recovery does not mutate a tooling pointer or supply an
optional upgrade authorization. A separately qualified executor is not evidence
that the unit has a sealed tooling context.

## Source-policy bootstrap and adoption

The repository owner may explicitly delegate one narrow source-policy
bootstrap decision for the independent authority policy/verifier and the
immutable NONPASS producer/recovery repair. That decision prospectively
evolves the locked-source prerequisite for those deliveries; it does not claim
the previous contract already exempted them. Record the exact reviewed source
candidates and complete path/mode/length/SHA256 sets. Preserve private task
details outside portable source.

This lane requires independent source review, the complete affected checks,
fresh exact base-owned protected Static admission, all required hosted dynamic
checks, ordinary merge and exact landing readback. The delegated source-policy
decision is separate from the static signature. Static authorization v1 keeps
its existing purpose and false execution/publication flags. No bootstrap
decision grants native writes, expands the current unit, accepts a result or
authorizes a later candidate independently of its exact evidence.

Adopt the independent authority A first. The downstream repair executor B
must bind A's actual repository/commit/tree and COMPLETE tracked path/mode/
length/SHA256 closure in its own independently adopted source configuration.
Request `trusted_authority_root` is a location only. An unconfigured binding,
alternate checkout/key/policy or changed A source must refuse before import.
A derives its root from its installed entrypoint and verifies clean exact Git
and physical bytes. B cannot choose A's policy or trusted key through a DTO.

## Two separate signed decisions

The read-only A verifier uses the public owner SPKI pinned in
`config/native-nonpass-recovery-authority.json`. Signing remains external.
Use the canonical RSA-PSS-SHA256 primitive, strict JSON, unique audit identity
and canonical UTC seconds. No private key, signing selector or credential is
stored in this policy.

`native_nonpass_repair_qualification.v1` is an exact owner source-qualification
attestation. It binds A's anchor, B's full committed executor closure, complete
base/head changed artifact set, a genuine normal two-parent source landing
with exactly B's tree, and retained source review, focused conformance, Static,
all three required dynamic checks, policy landing and implementation landing
originals. The verifier rehashes those originals and Git objects. The issuer
must inspect their actual outcomes before signing; a typed file alone is not
proof that a test or publication ran. This attestation supplies source
qualification only, no native acceptance. Changed source needs a fresh exact
attestation.

`native_nonpass_recovery_authorization.v1` has a distinct purpose:
`nonaccepting-corrective-freeze`. It binds the raw actual v4 request, A and B,
the source qualification's raw digest, the exact current project/unit/control
and ledger CAS, immutable source lock/map, original failure tuple and exact
audit-inert defect digest. It grants no PASS, acceptance, source-scope expansion,
publication or runtime credit. A static owner comment is not this decision.

Create the read-only signing request with
`New-NativeNonpassRecoveryAuthorizationRequest -WorkspaceRoot <workspace>
-RequestPath <actual-v4-input> -ExecutorRoot <qualified-B>`. It independently
reads source, qualification and current controls. Root's separate issuer must
review and sign that exact request-derived payload. No authorization is
generated by a caller boolean or by candidate self-tests.

## Verification and dispatch

Run `scripts/Invoke-NativeNonpassRecoveryAuthority.ps1` with `WorkspaceRoot`,
`RequestPath` and `ExecutorRoot`. Default operation verifies only. Explicit
`-Execute` verifies fresh qualification, signature, purpose, current hashes and
complete A/B source closure before a new isolated PowerShell child dispatches
only the fixed native `FreezeCandidate` entrypoint and exact v4 input. No
arbitrary command, shell or ambient token is accepted. Tracked A/B source files
remain protected by read handles through actual child exit and stream EOF.

B must independently invoke
`Assert-MorphospaceNativeNonpassRecoveryAuthorization` before any write. Its
four arguments are `WorkspaceRoot`, actual parsed `Request`, independently
observed `CurrentBindings` and `ExecutorRoot`. CurrentBindings includes the
physical `request_path`, raw request/control/source hashes, event length/tail
and final repository identities. A recomputes them; it does not accept them as
trusted evidence. B's structural native origin, defect classification,
transaction, source scope and final-live guards remain mandatory.

Interrupted recovery uses `mode:pending` with the exact original native intent
path and raw SHA. It reauthenticates the signed original preimage, current
unexpired grant, source and actual original-or-target partial projections.
It does not regrant authority or treat an incomplete intent as committed.

`Assert-MorphospaceNativeNonpassRecoveryHistory` authenticates the exact owned
raw request, native v6 intent/completion, canonical event prefix/placement and
target marker using A's trusted existing ledger structural owner in an
isolated runspace. Original created/completed times come from those real
records, not a supplied clock value. The signature must have been valid at
both times. Completed history is not made to expire retroactively. Old B
closure is derived from immutable Git objects; mutable historical source
payloads are not required to survive. Raw signed authorizations, qualification,
request and native transaction originals remain mandatory.

This correction accounts for precisely declared unavailable NONPASS payloads.
It neither claims those old bytes were retained nor changes old receipt,
Return, ledger, accepted checkpoint or PASS artifact meaning. The next ordinary
native lifecycle still requires its actual qualified evidence.

## Focused conformance

Within one native v4 call, the trusted module may hold the complete verified A
and B source files and their directory ancestry. Windows handles deny source
writes and source-path deletion or rename until the call closes its private
scope. Repeated proofs still read the request and all current authorization,
qualification and workspace evidence, and recheck Git identity, cleanliness
and unsafe selectors. Only the held physical source closure is reused. The
scope cannot cross workspace, raw request, executor or owning thread, and is
cleared in `finally`. Other platforms rehash the complete physical closure on
each proof. `scripts/Test-NativeNonpassRecoverySourceScope.ps1 -SelfTest`
checks observation counts, mutation and rename refusals, fresh Git guards,
scope isolation and actual handle release without a timing threshold.
The source scope grants no request authority. Nested checks still authenticate
their own live, pending or historical records, including native-owned request
aliases and older committed recovery requests, using their original signatures
and transaction evidence.
The owner request is held as read-only data with delete sharing: its native
pending-to-receipt rename remains supported, while the same held bytes are
rehashed on scope assertions. Each actual C record path is still read and
authenticated independently.

`scripts/Test-NativeNonpassRecoveryAuthority.ps1 -SelfTest` creates real Git
source identities and ephemeral signing policies. It checks wrong signer,
policy, purpose, source head/tree/path set, stale controls/expiry, altered or
extra defects, accepted targets, replay and verify-only behavior. Its isolated
child marker is dispatch evidence only. Optional test-only
`-RecoveryAdapterPath <actual-B-adapter>` checks the independently pinned B
adapter, missing adoption, fake locators and changed A policy/module bytes.
These signature/CAS boundary fixtures do not claim genuine native lifecycle
or production source qualification; the B conformance consumer must exercise
real native failure/Return/correction/retry/retirement and history.
